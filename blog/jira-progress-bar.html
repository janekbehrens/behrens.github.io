Jira Progress Bar: Setup, Examples and Dashboard Views

Choose a progress field, understand its calculation and make it visible where your team works. This guide uses the current Visual Progress Tracker fields, with an example you can check by hand.

Where a Jira progress bar helps

A workflow status tells you where an issue is. A percentage lets you compare issues in a list or dashboard, provided everyone understands what the number measures. A status-based 50% means the issue reached a mapped workflow step; it is not proof that half the effort is complete.

Jira already has progress views, including its timeline progress bars. This guide covers a different task: adding a reusable progress field to an issue and showing it in list columns and dashboard gadgets with Visual Progress Tracker for Jira.

Try the same controls with sample data: open the interactive Visual Progress Tracker demo. No Jira installation is needed to explore it.

Choose what your percentage means

1. Manual: an estimate from the person doing the work

Use Progress Bar (Manual) for research, design or work with milestones outside Jira. Set the value with the slider or quick buttons and save it. Agree what 25%, 50% and 100% mean for your team; otherwise two people can report different numbers for the same situation.

2. Status: a shared workflow mapping

Progress Bar (Status) uses a site-wide mapping maintained by a Jira admin. For example: To Do = 0%, In Progress = 50%, In Review = 75%, Done = 100%. Map every status you use: an unmapped status contributes 0%. This is useful when workflow steps are a consistent proxy for progress.

3. Subtasks: the average progress of the children

Progress Bar (Subtasks) averages the progress of the subtasks. If there are no subtasks, it uses the child issues, such as stories inside an epic. Done children count as 100%; other children use their status mapping. A parent without children shows a dash. This is not simply the percentage of children marked Done.

Example subtaskStatusContribution
API endpointDone100%
ValidationDone100%
TestsIn Progress50%
DocumentationTo Do0%

With that mapping, the average is (100 + 100 + 50 + 0) ÷ 4 = 62.5%, displayed as 63%. Two of four subtasks are done, which is 50%. Both figures can be correct because they answer different questions. The example is illustrative, not a customer result.

Compare issues in the Jira list view

Add your field through the column picker in the project List view. Each cell shows a colored dot and percentage. If the field is missing, first check that a Jira admin added it to the relevant screens. Keep the list focused on one kind of progress: a manual estimate and a child-status average are not interchangeable measures.

Set up the fields with a Jira admin

  1. Install Visual Progress Tracker for Jira from the Atlassian Marketplace.
  2. Under Jira settings → Work items → Fields, create the Progress Bar field type you need.
  3. Add the field to the project screens where people need to see it.
  4. For Status and Subtasks, check Apps → Visual Progress Tracker → Status Mapping, then save the mapping.
  5. Open an existing issue to check the result, then add the field as a list column if needed.

For the exact screens and troubleshooting, use the field setup documentation.

Why list colors and issue bars can differ

The default bands are red below 34%, yellow from 34% to 66%, and green from 67%. A Jira admin can change thresholds for issue bars and both dashboard gadgets. List view dots always use the fixed 34% and 67% boundaries. A green bar is a percentage band, not a promise that a deadline will be met.

Find issues using saved progress values

In Jira advanced search, replace the project key and field names below with your own. These queries read saved custom-field values; check the refresh guidance below before relying on them for a report.

Issues below 50% in an active sprint

project = MYPROJ
AND sprint in openSprints()
AND "Progress Bar (Status)" < 50
ORDER BY "Progress Bar (Status)" ASC

Epics to inspect

project = MYPROJ
AND issuetype = Epic
AND statusCategory != Done
AND "Progress Bar (Subtasks)" < 25
ORDER BY updated ASC

Your open issues

project = MYPROJ
AND assignee = currentUser()
AND statusCategory != Done
ORDER BY "Progress Bar (Manual)" ASC

Show the same progress on a dashboard

Use Progress Tracker Overview for a sortable issue table, or Epic Progress Tracker for one bar per epic. The sprint dashboard walkthrough shows how to choose a sprint filter and interpret the average.

Why a saved value can be out of date

Status and Subtask fields refresh when someone opens an issue. After changing mappings or adding fields, an admin can use Recalculate All Fields; it is normally limited to once every seven days. Dashboard results are cached for up to five minutes per viewer and have a Refresh button. See the recalculation documentation before investigating a mismatch.

Which field should you start with?

Start with Status when the workflow represents meaningful checkpoints. Choose Subtasks when the child issues represent the work you want to summarize. Use Manual when progress needs an explicit human estimate. For story-point weighting across an epic, use the Epic Progress Tracker gadget rather than treating the Subtasks field as weighted.

Frequently asked questions

Do I need scripting or automation rules?

No custom script is needed for these fields. Installation, field creation and mapping changes still require the appropriate Jira administrator permissions.

Does 63% mean that 63% of the subtasks are done?

Not necessarily. The Subtasks field averages child progress, including partial percentages for unfinished children. Done count and average progress are different measures.

Can I use several progress fields on one issue?

Yes. Manual, Status and Subtasks can appear side by side. Give each a clear purpose so readers know which number to use.
