Jira Sprint Health Dashboard: A Practical Setup Guide

Combine a sprint-level summary with a table that helps you choose the next conversation. Here is a dashboard recipe, a sprint filter and a clear explanation of what the average does and does not mean.

Start with the questions your dashboard must answer

A useful sprint dashboard separates delivery, scope and individual work. Is the sprint moving toward its goal? Has the scope changed? Which issues need a decision today? One average progress bar cannot answer all three. Build a small dashboard with a sprint summary and an issue-level table.

Use native sprint reporting for the overall picture

Jira provides Sprint Health and Sprint Burndown gadgets. Start with those when you need sprint-level health or remaining work; the Atlassian gadget list describes the native options. Add an issue progress table when the summary leaves you asking which tickets to inspect.

The recipe below uses Visual Progress Tracker for the issue table. It complements sprint reporting; it does not calculate a delivery forecast or replace your sprint goal.

Pick one progress measure for the issue table

Use Status for workflow checkpoints, Subtasks for the average progress of each issue’s children, or Manual for estimates people maintain. The progress field guide explains the calculation and setup. For this walkthrough, choose Status with To Do = 0%, In Progress = 50%, In Review = 75%, Done = 100%.

Build a sprint-focused Progress Tracker Overview

  1. Open a Jira dashboard you can edit and choose Add gadget.
  2. Add Progress Tracker Overview and select your project.
  3. Set Progress Calculation to Status for this example.
  4. Enter the additional JQL filter below and choose 10, 25 or 50 rows per page.
  5. Save Configuration. Click the Progress column header to inspect lower values first.
sprint in openSprints() AND issuetype in (Story, Task, Bug)

The project is selected separately, so the filter only needs the extra conditions. This example leaves out subtasks and epics to avoid mixing parent summaries with their children. Adjust the issue types to match your project. If multiple sprints are active, openSprints() can include more than one; use a specific sprint ID, such as sprint = 123, when you need exactly one sprint.

Turn the numbers into a standup conversation

Checkout testsDone100%
Payment reviewIn Review75%
Address formIn Progress50%
Release notesTo Do0%

The illustrative average is 56% after rounding. Only one of the four issues is done: the completion count is 25%. Neither figure measures remaining hours. Ask why Release notes has not started, whether Payment review is waiting on someone, and whether Address form has a blocker. A green percentage alone cannot tell you whether the sprint goal is safe.

You can also add the progress field to the project List view for issue triage outside the dashboard. Its colored dots use fixed 34% and 67% boundaries; dashboard bar thresholds can be changed by a Jira admin.

Check these settings before trusting a report

  • Map every workflow status in use. Unmapped statuses count as 0%.
  • Keep the filter focused. The gadget loads up to 500 issues; narrow it if the limit notice appears.
  • Sort using the table headers. An ORDER BY clause in the gadget filter is ignored.
  • Check data age. Results can be cached for up to five minutes per viewer; Refresh loads current data.
  • Review missing values: issues shown with a dash are excluded from the average. The number is an average of available values, not automatically every issue in the sprint.

If you need sprint-to-sprint planning context, add the velocity chart guide; for longer-running work, use the epic dashboard guide.

Frequently asked questions

Can I filter the progress gadget to one sprint?

Yes. Select the project and add sprint = 123 with your sprint ID in Additional JQL Filter. sprint in openSprints() includes active sprints and can match more than one.

Is average progress the same as sprint completion?

No. A status-based average includes partial progress assigned to unfinished issues. Completion counts only finished work. Use both in context and keep the sprint goal visible.

Do I need a Jira admin for the whole dashboard?

A Jira admin is needed to install the app, create fields and save mappings. Configuring a dashboard gadget requires permission to edit that dashboard.
