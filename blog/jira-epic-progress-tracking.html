Jira Epic Progress: Issue Count, Story Points and Dashboards

An epic can be 65% progressed while only 50% of its story points are done. Learn why those numbers differ, which view to use and how to give stakeholders a dashboard they can interpret.

Choose between a timeline, a field and a dashboard

Jira already shows parent progress in its timeline, with segments for child status categories. For a company-managed Scrum board, the Epic Report provides another native view. Start there if those views answer your question.

Use a progress field when people need the percentage on the epic itself or in a list column. Use the Epic Progress Tracker gadget from Visual Progress Tracker when stakeholders need one bar per epic on a shared dashboard, with a choice of issue-count or story-point weighting.

What the Subtasks field actually counts

The Progress Bar (Subtasks) field first uses subtasks; if there are none, it uses child issues such as stories under the epic. It averages those children’s progress. Done children count 100%; unfinished children use the site-wide status mapping. It does not recursively sum every level of the hierarchy or weight the field value by story points.

For field creation and the three field types, follow the Jira progress bar guide. The rest of this article focuses on choosing and interpreting an epic-level view.

In this illustrative epic, one of three stories is done: 33% by done count. The equal-weight progress average is (100 + 50 + 0) ÷ 3 = 50%. With story-point weighting in the Epic Progress Tracker gadget, the average is (5 × 100 + 3 × 50 + 2 × 0) ÷ 10 = 65%. Only 5 of 10 story points are done. The partial credit for Profile explains the difference.

Choose the metric with your audience before comparing epics. Issue count treats a small task and a large story equally. Story-point weighting depends on estimates; unestimated issues have no weight. Neither measure is a delivery date or a comparison of productivity between teams.

Use Details to understand a field value

On the epic, open Details next to the Subtasks field to inspect each child’s status and percentage. If the result looks too low, check unmapped statuses before assuming work has stalled. A parent without children shows a dash. Status and Subtask field values refresh when the issue is opened; changed mappings may also require an admin recalculation.

Compare epics on a shared dashboard

The dedicated gadget shows each epic as a row. Its top bar is the average of the epic rows, not a single story-point-weighted roll-up across all epics. Use the row values for the comparison and read the Done column alongside the percentage.

Set up Epic Progress Tracker

  1. Install Visual Progress Tracker for Jira, then open a dashboard you can edit.
  2. Choose Add gadget and add Epic Progress Tracker.
  3. Select the project and set Group by to Epic.
  4. Choose Issue count or Story points under Progress metric.
  5. Optionally add a JQL condition to select the epics, choose rows per page and save the configuration.
labels = "customer-portal"

In Epic mode, Additional JQL Filter selects the epics, not their child stories. For the example above, put the customer-portal label on the epics you want to include. Do not use a sprint filter here expecting it to select stories inside otherwise unmatched epics. For an issue table limited to sprint work, use Progress Tracker Overview instead.

Results can be cached for up to five minutes per viewer; Refresh loads current data. For configuration details and limits, read the Epic Progress Tracker documentation.

Frequently asked questions

Does Jira already show epic progress?

Yes. The timeline shows parent progress from child status categories, and company-managed Scrum boards have an Epic Report. An app is useful when you need a progress custom field or a dedicated dashboard view.

Does the Subtasks field weight stories by points?

No. It averages child progress equally. Choose Story points in the Epic Progress Tracker gadget when you want a weighted dashboard metric.

Why can the bar be higher than the Done figure?

The bar includes mapped partial progress for unfinished issues. Done counts only completed issues or their points. A 65% progress bar can therefore coexist with 50% of story points done.
