Fakten aus Git, stets aktuell auf der Seite

Ein Synchronisationsblock zeigt einen Wert, eine Tabelle, einen Abschnitt oder Code aus einer Datei deines Repositorys. CodeDoc aktualisiert ihn bei jedem Push, täglich, wöchentlich oder wenn du auf „Update now“ klickst.

  • Werte aus YAML oder JSON, ein README-Abschnitt, der neueste CHANGELOG-Eintrag, ein Ausschnitt zwischen Markierungskommentaren, ein Zeilenbereich oder die gesamte Datei.
  • Normaler Seitentext: Confluence-Suche, Export und Seitenhistorie enthalten ihn.
  • Eine neue Seitenversion nur bei geänderter Datei. Keine KI beteiligt.

Link einfügen, Inhalt wählen, Vorschau prüfen

Gib / auf einer Seite ein, wähle „CodeDoc Sync Block“ und füge den Link zu einer Datei ein. CodeDoc füllt Repository, Branch und Pfad aus.

  • Wähle Schlüssel, Überschriften oder Ausschnitte aus der Datei, statt sie einzutippen.
  • Die Vorschau zeigt das Ergebnis vor dem Speichern; bei Problemen wird der nächste Schritt erklärt.
  • Nur Job Operator und Administratoren wählen aus, woher Inhalte stammen.

Das neueste Release neben jeder Version

Optional für Werte und reguläre Ausdrücke: CodeDoc sucht das neueste Release des durch den Wert bezeichneten Produkts und zeigt einen Status wie aktuell, Aktualisierung verfügbar oder Ende der Unterstützung.

  • Docker-Hub-Images, npm- und PyPI-Pakete, GitHub-Releases.
  • Unterstützungszeiträume von endoflife.date für Produkte wie nginx, PostgreSQL oder Node.js.
  • Nur der öffentliche Name des Images oder Pakets wird an die Registry gesendet.

Editionen

Standard und Advanced

Beide beginnen mit 30 Tagen kostenloser Testphase; Preise pro Nutzer findest du im Marketplace-Eintrag.

Standard

Alle CodeDoc-Funktionen; KI-Seiten mit deinem eigenen KI-Schlüssel.

  • Synchronisationsblöcke mit Versionsprüfung
  • GitHub, GitLab, Bitbucket Cloud, Azure DevOps und dein eigener GitHub-Enterprise- oder GitLab-Server
  • KI-Seiten mit eigenem Anthropic-, OpenAI- oder Google-Gemini-Schlüssel
  • Prüfung vor der Veröffentlichung, Rückgängigmachen, Zeitpläne, Webhooks, Rollen

Advanced

Standard plus Atlassian AI, damit KI-Seiten keinen eigenen Schlüssel benötigen.

  • Alles aus Standard
  • Atlassian AI: Claude-Modelle auf der Atlassian-Plattform, mit Modell „Balanced“ oder „Fast“
  • 100 Credits pro Monat und Instanz, 100 für die gesamte Testphase, mit Nutzungsanzeige
  • Dein eigener KI-Schlüssel bleibt als Alternative verfügbar

Ohne aktives Abonnement, etwa nach der Testphase, hält CodeDoc 3 Synchronisationsblöcke aktuell, und du kannst 1 KI-Seite mit deinem eigenen KI-Anbieter einrichten. Zuvor eingerichtete Blöcke und KI-Seiten laufen weiter.

FAQ

Häufige Fragen

Weitere Antworten findest du in der Dokumentation, oder schreibe an support@janekbehrens.de.

Was ist ein Synchronisationsblock?
Ein Block, den du auf jeder Confluence-Seite einfügst mit /. Er zeigt einen Wert, eine Tabelle oder einen Abschnitt aus einer Datei deines Repositorys, etwa die aktuelle Version eines Helm-Charts oder den Installationsabschnitt einer README. CodeDoc hält ihn aktuell. Synchronisationsblöcke verwenden keine KI und verursachen daher keine Tokenkosten. Anleitung lesen.
Brauche ich einen KI-Schlüssel?
Nicht für Synchronisationsblöcke: Sie benötigen nur einen Git-Zugriffstoken mit Leseberechtigung. KI-Seiten benötigen Atlassian AI, enthalten in CodeDoc Advanced, oder deinen eigenen Anthropic-, OpenAI- oder Google-Gemini-Schlüssel. Mit eigenem Schlüssel rechnet dein Anbieter direkt mit dir ab; CodeDoc erhebt keinen Aufschlag.
Welche Git-Ereignisse aktualisieren eine Seite?
Mit dem CodeDoc-Webhook im Repository aktualisieren sich Blöcke und KI-Seiten mit der Einstellung „On every push“ bei Pushes von GitHub, GitLab, Bitbucket und Azure DevOps. GitLab-Merge-Request-Ereignisse sowie zusammengeführte Pull Requests in Bitbucket und Azure DevOps zählen ebenfalls; bei GitHub kommt eine Zusammenführung als Push an. Ohne Webhook wählst du tägliche oder wöchentliche Aktualisierung. Einzelheiten: Webhook-Einrichtung.
Welche Confluence-Version brauche ich?
CodeDoc benötigt Confluence Cloud. Die Forge-App läuft auf der Atlassian-Infrastruktur; es gibt keine Data-Center- oder Server-Version. Sie kann deinen eigenen GitHub-Enterprise- oder GitLab-Server lesen, wenn dieser aus der Atlassian-Cloud erreichbar ist.
Funktioniert CodeDoc mit einer GitHub-IP-Allowlist?
Ja. CodeDoc liest deine Repositories aus Atlassians Cloud, daher trägt ein Owner der GitHub-Organisation Atlassians ausgehende IP-Bereiche einmalig in die Allowlist ein. Details.
Wie lange dauert die Einrichtung?
Die meisten Teams sind in etwa 5 Minuten verbunden. Du benötigst einen Git-Zugriffstoken mit Leseberechtigung. KI-Seiten benötigen zusätzlich Atlassian AI (Advanced-Edition) oder deinen eigenen KI-Anbieterschlüssel. Der Schnellstart führt dich durch jeden Schritt.
Verlässt mein Code die Atlassian-Infrastruktur?
Synchronisationsblöcke senden nichts an einen KI-Anbieter. Für KI-Seiten ruft die Forge-Laufzeit die gewählten Dateien ab und sendet sie entweder an Atlassian AI (Advanced-Edition; der Code bleibt auf der Atlassian-Plattform) oder direkt an deinen eigenen KI-Anbieter. Zu keinem Zeitpunkt sind Server von Janek Behrens beteiligt. Einzelheiten stehen im Vertrauensportal (EN).
